# Architecture Decision Records

This directory contains Architecture Decision Records (ADRs) for the Open Operational State initiative.

## What Are ADRs?

An Architecture Decision Record captures a significant decision, the context in which it was made, and the consequences of the decision. ADRs provide a transparent history of why the project is shaped the way it is.

## When to Write an ADR

Write an ADR when:

- A locked decision is being made or revisited
- An architectural choice affects multiple repositories
- A scope or governance change is approved
- A significant trade-off is being made

## ADR Format

Use the following template for new ADRs:

```markdown
# ADR-NNNN: Title

## Status

Proposed | Accepted | Deprecated | Superseded

## Context

What is the issue or question being addressed?

## Decision

What was decided?

## Consequences

What are the positive, negative, and neutral consequences of this decision?

## References

Links to related issues, discussions, or documents.
```

## Naming Convention

Files should be named `NNNN-short-title.md`, starting from `0001`.
